# Office‑A — 年間リソース管理ツール

会社組織（部長 › 課長 › 課長代理 › 主任 › メンバー）の人員・案件・月別アサインをローカルで管理し、Excel に出力できるツールです。データはすべて `data/db.json` にローカル保存されます。

## 必要環境
- Node.js 22 以上（npm 同梱）

## 起動
```bash
npm install
npm run dev
```
ブラウザで http://localhost:5173 を開きます。

ビルド済みを 1 プロセスで動かす場合:
```bash
npm run build
npm start        # http://127.0.0.1:5174
```

## 画面
| パス | 内容 |
|---|---|
| `/` | ダッシュボード（受注金額合計・月別稼働（時間）・案件充足状況・役職別稼働） |
| `/schedule` | アサイン（人 × 月のマトリクス。案件チップをドラッグ&ドロップ、工数は時間で入力。パレットの案件名クリックで必要役割・人月の詳細） |
| `/org` | 組織ツリー（ドラッグで所属変更、インライン編集） |
| `/projects` | 案件（コード・受注金額・契約期間・必要役割（人数・必要人月）） |
| `/settings` | 役職階層・役割ステータス・年度開始月・1人月の時間・Excel 出力 / 取り込み・バックアップ |

## Excel 出力
サイドバーの「Excel出力」または設定画面から、表示中の年度を `.xlsx` でダウンロードします。
シート: `メンバー` / `案件` / `アサイン` / `稼働サマリ` / `説明`

工数は**時間**で扱います。**160h = 1人月**（設定画面「会社」の「1人月の時間」で変更可）。内部では人月比（`ratio` = 時間 ÷ 1人月時間）で保持します。
案件の**受注金額**は案件全体の契約額をそのまま保持・表示するだけで、稼働時間と掛け合わせる計算はしません。
案件の必要役割には**必要人月**（その役割の案件全期間の必要工数）を持たせ、アサイン済み人月（案件の全月の Σ人月比）と比べて充足を表示します（案件カードのリング = 人月充足率）。

## Excel からの取り込み
出力した `.xlsx` を Excel で編集し、読み戻せます。

1. 設定画面「Excel」セクションで年度を選んで `.xlsx` をダウンロード
2. Excel で編集して保存（ルールはファイル内の `説明` シートにも記載）
3. 同セクションの「Excelから取り込み…」でファイルを選ぶ → 追加・更新・削除の件数と警告のプレビューを確認 → 「取り込む」

ルール:
- **ID 列は変更しない**（既存データとの対応付けに使用）。新しい行は ID を空欄に。ID が空なら メンバーは名前、案件は案件コードで照合し、見つからなければ新規作成
- 行の追加・削除が可能。シートから消したメンバー / 案件は削除され、そのアサインも全期間分削除（データ行が 1 行もないシートは削除扱いにしない）
- `メンバー`: 名前 / 役職（役職名、未登録なら最下位の役職として作成）/ 上長（名前、空欄はトップ）/ 備考。兄弟内の並びはシートの行順
- `案件`: 案件コード / 案件名 / 受注金額（円、案件全体。旧ファイルの `単価` 列も受注金額として読む）/ 開始・終了（`YYYY-MM`）/ 必要役割（`PM×1 (2.5人月), PL×1 (1人月), 開発メンバー×3 (12人月)` = 役割名×人数 (必要人月)。必要人月は案件全期間の合計で 0.01 以上・小数 2 桁。`(N人月)` を省略した旧形式 `PM×1` は 人数 × 案件の月数 とみなす。未登録の役割は作成）/ 色（`#RRGGBB`）/ 備考
- `アサイン`: 見出しの 12 ヶ月分のアサインをシートの内容で**置き換え**（他の年度は変更なし）。セルは 1 件 1 行で `案件コード [役割] 工数h`（例 `PRJ-2026-001 [PL] 80h`、`PRJ-2026-002 160h`。出力では役割なしなら `[役割]` を省略し、時間は常に書く）。工数は 時間 ÷ 1人月時間（既定 160）で人月に換算。`H` や全角 `ｈ` も可、工数を省略した行は 1人月。工数は 1h〜2×1人月時間（既定 320h、残業込み）に丸め（警告あり）。旧形式の `×0.5` / `x0.5` / `*0.5`（人月比）も読み込み可。未登録の案件コードや読めない行は警告を出して読み飛ばし
- `稼働サマリ`（案件 × 月の稼働時間・人月、受注金額）・アサインの 階層 / 年間稼働列 / 集計行（月別稼働人月・月別稼働時間）は参照用で読み込まない。設定（会社名・年度開始月・1人月の時間）は変更しない

API: `POST /api/import.xlsx`（本体は xlsx のバイト列、`Content-Type: application/octet-stream`）。`?dryRun=1` で保存せずレポートのみ返します。

## データ
- 保存先: `data/db.json`（自動保存。直前の状態は `data/db.bak.json`）
- バックアップ / 復元: 設定画面からエクスポート・インポート
- 初回起動時はサンプルデータが投入されます。不要なら設定画面で削除するか `data/db.json` を削除して再起動してください。

## トラブルシューティング
**`[web] Error: EBUSY: resource busy or locked, watch` が出る（Windows）**
Vite のファイル監視がロック中のファイルに当たったときのエラーです。`data/` と `dist/` は監視対象から除外済みですが、それでも出る場合は次を確認してください。
- OneDrive / Dropbox などの同期フォルダやネットワークドライブではなく、`C:\Office-A` のようなローカルフォルダに置く
- WSL と Windows をまたいだパス（`/mnt/c/...`、`\\wsl$\...`）で実行しない
- 開発サーバーを使わず `npm run build && npm start` で起動する（監視を行わないため発生しません）
